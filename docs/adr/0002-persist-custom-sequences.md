# Introduzir persistência para sequências de acordes customizadas

The project previously hardcoded the catalog of "famous chord sequences" in two places: the backend kept a dict of 6 sequences in `main.py` mapped to precomputed tags (`SEQ_FAMOSA`) on songs in `data/top/dataset_final.csv`, and the frontend `#/porsequencia` hardcoded 4 of them in JavaScript. That approach only allowed the fixed set to be used for search and could not grow without code changes/deploys. The feature requires that any visitor can register a new sequence anonymously and search for songs by it, with the catalog persisted in a database so it survives container restarts. At the same time, the catalog of songs and genres must remain in the existing CSV loaded in memory (no migration of music/genre data), and the app must stay local-only in a single Docker container with no additional external services.

We decided to persist only the sequences catalog in **SQLite** (via Python's stdlib `sqlite3`) stored as a file on the local filesystem. SQLite is embedded, requires no external process/service, fits the single-container local-only deployment already established by ADR 0001, and is easy to wire into the existing Flask app. For lookup of registered sequences we will expose API endpoints to list and create sequences (open and anonymous), and extend `/similares?sequencia=...` to resolve custom sequences not present in the hardcoded map by computing matches in real time against `musica.cifra` (the ordered list of chords produced by `limpa_cifra`, preserved in `Musica.cifra`) using ordered subsequence matching, while keeping the existing tag-based lookup for the original 6 sequences unchanged to guarantee identical results for regression. The frontend `#/porsequencia` will be updated to load the catalog from the backend (no longer hardcoded) and allow creating new sequences. All endpoints will continue to return `json.dumps(...)` as plain strings as per existing convention.

This keeps the change minimal in scope (only sequences), preserves backward compatibility for the original 6 sequences, satisfies persistence across restarts when `data/` is mounted as a volume (documented run command: `docker run -p 8080:8080 -v "$(pwd)/data:/app/data" ciframe`; the DB path can also be overridden with `SEQUENCIAS_DB_PATH`), and avoids introducing external services or reworking the CSV-backed in-memory music/genre model.
